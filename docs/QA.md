## Исправленные проблемы

- Dev-прокси Vite менял Host, CSRF-проверка отклоняла login. Установлен changeOrigin:false, проверка безопасности сохранена; browser-сценарии повторены успешно.
- Vitest захватывал Playwright spec. Разведены области поиска тестов.
- Зависимости FastAPI/Starlette, pytest, Vitest имели известные проблемы безопасности. Установлены проверенные новые версии; multipart удалён, потому что API читает ограниченный raw CSV поток и не нуждается в multipart.
- Полные дубли с бюджетами `12` и `12.00` первоначально могли различаться строковым представлением. Ключ использует Decimal: числовые варианты совпадают; регрессионный тест добавлен.
- Дата в самом начале календаря могла вызвать переполнение при вычислении недели. Теперь возвращается понятная ошибка; регрессионный тест добавлен.
- Docker COPY первоначально сохранял права каталогов, недоступные непривилегированному пользователю. Добавлен --chown=10001:10001; контейнер повторно собран.
- Ответ Pydantic на невалидный login мог отражать входное поле. Теперь текст ошибок входа обезличен, размер запроса ограничен даже без Content-Length.

## Что не подтверждено внешним доступом

- Нет Telegram-токена и allowlist в окружении. Обработчики проверены mock-транспортом: авторизация до скачивания, отказ группам/чужим ID, лимиты, неверный CSV, одинаковые расчёты, безопасный экспорт, повтор файла, занятость и сброс состояния после ошибки. Реальный Bot API, доставка сообщений и непрерывная работа worker требуют токена и хостинга.
- Нет Vercel token/project/org и доступной Vercel-интеграции. Конфигурация подготовлена; live URL и фактическая публикация не заявлены. После импорта проекта выполнить smoke checklist из README.
- Управляемый Chromium запрещает file://. Автономность проверена отрисовкой точных локальных HTML-байтов через setContent с offline:true. Прямой двойной щелчок на машине пользователя отдельно не тестировался.
- Обычная Docker-сборка не смогла разрешить DNS package registry из build-контейнера, в том числе с переданными стандартными proxy build args. Для проверки упаковки скачаны те же wheels через доступную сеть с --require-hashes, затем выполнена offline-сборка с --no-index/--find-links и сохранённой проверкой хешей. Статус smoke-теста записан ниже; обычную сетевую сборку на VPS нужно повторить.
- Rate limit API in-memory не глобален между Vercel instances. Для приватной production-версии нужна внешняя защита входа на уровне Vercel Firewall/Deployment Protection. Публичное демо не открывает загрузку CRM.
- Установка зависимостей и локальная сборка не подтверждают публикацию cloud snapshot или восстановление в новой задаче.

## Финальная сквозная проверка и конфигурация среды

Запущены документированные команды scripts/run_local.py api и npm run dev. Через реальный Vite proxy выполнены вход, обработка оригинального CSV и полное сравнение JSON с CLI, проверка всех пяти баллов звонков и двух независимых альтернатив, затем logout и повторный отказ приватного API. Проверка прошла. Все пять оригиналов повторно сверены по SHA-256, изменений нет.

В черновике облачной среды сохранены install_script, start_skill, требования переменных TELEGRAM_BOT_TOKEN/TELEGRAM_ALLOWED_USER_IDS и разрешённый домен api.telegram.org; существующие сетевые presets сохранены. Ответ инструмента: status=saved, requires_publish=true. Это не публикация и не применение настроек к работающей машине. Для повторного использования пользователь должен просмотреть и сохранить настройки среды, затем опубликовать её.

Контейнерный smoke-тест после исправления прошёл: UID 10001, read-only filesystem, отключённая сеть, общая аналитика вычисляет ожидаемый результат; бот без токена завершается с понятной ошибкой. docker compose config --quiet также успешен. Проверена offline-вариация сборки с теми же хешированными пакетами, не live-подключение к Telegram.
