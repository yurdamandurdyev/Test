# Архитектурные решения

## Одна система, один расчёт

```text
CLI ────────────────┐
React → FastAPI ────┼── Python analyze(bytes) → отчёт → JSON / безопасный CSV / текст
Telegram worker ───┘

Проверенные аннотации → score_calls → приватный API + автономный HTML и CSV
```

Python standard library отвечает за CSV, Decimal, даты, валидацию и агрегацию. Поэтому обязательный скрипт работает без установки библиотек. API и бот добавляют транспорт, но не меняют формулы. Контракт JSON типизирован в TypeScript, проверка входных данных остаётся на сервере.

React + TypeScript + Vite; Tailwind CSS подключён к сборке, визуальные токены и большая часть стилей централизованы в style.css. Lucide — иконки, Recharts — один график, загружаемый отдельным чанком. Таблица с поиском и пагинацией не нуждается в тяжёлом grid-компоненте при лимите 10 000 строк. Переиспользуются Panel, Metric, Empty, Sources; фильтрация/форматирование отделены от UI. Никаких фиктивных изменений конверсии или выручки.

## Статичность и динамика

Звонки оценены по предоставленным пяти расшифровкам вручную с явными аннотациями и цитатами. Их веса, валидация свидетельств, агрегаты и экспорт вычисляются кодом. Это не сервис автоматической оценки произвольных новых разговоров: такого обещания нет. Новые разговоры требуют проверенных аннотаций по той же схеме.

CSV загружается и анализируется заново по каждому запросу. Это рабочий динамический модуль, не статичный отчёт. В браузере данные хранятся только в состоянии текущей вкладки. Обновление страницы сбрасывает загруженную CRM, возвращая демо; выход очищает приватные данные. Токен сессии — HttpOnly-cookie с подписью и сроком 8 часов, а не содержимое CRM.

Демонстрационный CSV — отдельный, явно помеченный синтетический набор. Телефоны DEMO-* намеренно невалидны и показывают качество данных. Аналитика оригиналов не смешивается с демо. Авторизация открывает реальные звонки только при наличии приватного CALLS_ANNOTATIONS_PATH или серверного CALLS_ANNOTATIONS_JSON; файлы оригиналов не входят в публичную поставку.

## Размещение и масштаб

Vercel: статическая Vite-сборка + короткие запросы Python ASGI. Нет фонового polling, записи CRM на диск, SQLite или ожидания LLM. API анализирует до 2 МБ / 10 000 строк и возвращает отчёт за один запрос. Собственные ограничения заданы ниже типовых лимитов тела serverless-запроса; реальные ограничения тарифа нужно проверить при подключении проекта.

Бот: один Docker worker с long polling на постоянно работающем VPS или сервисе background workers. Он не зависит от компьютера пользователя. Webhook на Vercel потребовал бы устойчивой очереди/хранилища идемпотентности и усложнил этот объём задачи; выбран polling. Одновременно запускается только один экземпляр для одного токена.

База данных не добавлена: нет требования долговременного хранения, а CRM содержит персональные данные. Поэтому бот не формирует URL подробного отчёта. Для истории и персональных ссылок будущая версия потребует аутентификации отдельных пользователей, ACL, базы с TTL, удаления и аудита доступа.

## Границы безопасности

Пароль команды достаточен для небольшого закрытого пространства, но не заменяет multi-tenant SSO/RBAC. Браузерные мутации требуют специальный заголовок и same-origin; CORS не разрешён. В production cookie Secure и HTTPS обязательны. Ключ подписи случайный, минимум 32 символа; пароль минимум 16. Смена SESSION_SECRET аннулирует все сессии.

Лимитер входа in-memory — защита одного процесса, не глобальный лимитер Vercel. Перед открытием приватного режима используйте Vercel Firewall rate limit для /api/login или Deployment Protection (если доступно в вашем тарифе). Без него оставляйте приватный режим выключенным; публичное демо не принимает произвольные CSV.

HTML экранирует значения, React не использует dangerouslySetInnerHTML. Экспорт CSV защищён от формул, телефоны с + экспортируются как текст. Бот не включает Markdown/HTML parse mode, проверяет тип/расширение/размер и ID до скачивания. Повторы отслеживаются хешами на 10 минут, до 1000 записей; перезапуск забывает хеши. Это ограниченная защита от повторов, не гарантия exactly-once доставки.

Веб не сохраняет CRM на диск. Telegram-файлы существуют в памяти на время обработки; сообщения и документы, отправленные пользователю, остаются в Telegram по правилам платформы. Отказ от сохранения на нашем сервере не означает удаления из Telegram.

## Проверки и воспроизводимость

uv.lock и package-lock.json фиксируют окружение. requirements.txt экспортирован с хешами из uv.lock для Vercel/Docker. Pytest проверяет ядро, CLI, HTTP и бот; Vitest — только клиентское представление; Playwright — загрузку, экспорт, навигацию, ошибки и размеры экранов. Дублирование бизнес-логики в TypeScript намеренно отсутствует.

Тесты Telegram используют mock транспорта: они подтверждают обработчик и вычисления, но не реальное подключение к Bot API. Проверка опубликованного Vercel deployment и работающего Docker worker выполняется после предоставления доступов; локальная сборка не выдаётся за деплой.
