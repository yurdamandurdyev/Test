# Бесплатная демонстрация: запуск без токена Vercel

## Что подходит и что ещё не подтверждено

Для небольшой демонстрации webhook совместим с существующим FastAPI: JSON обновления приходит в HTTP-запросе, CSV скачивается напрямую из Telegram, расчёты выполняет прежнее Python-ядро, результаты отправляются до ответа 200. Бесконечного процесса и фоновых задач нет. CSV ограничен 2 МБ и 10 000 строк. Входящий webhook ограничен 64 КБ. Экспорт идёт из функции в Telegram, а не в HTTP-ответ Vercel.

Выбран Vercel Hobby + бесплатный Redis через Marketplace (Upstash), если бесплатный план доступен в вашем аккаунте. Redis необходим для блокировок между экземплярами serverless. Только ID, хеши и отметки этапов, без имён, телефонов, CSV и отчётов. TTL: блокировки 90 секунд, повтор файла 10 минут, обработанное update_id и этапы 7 дней. Закрытые CSV не попадают в публичное демо.

Конфигурация запрашивает `maxDuration: 60`; внутри обработка ограничена 25 секундами, освобождение блокировок — ещё до 8 секунд. Это выбранные ограничения проекта, **не утверждение о текущих лимитах тарифа**. При недоступности Redis или таймауте возвращается 503: Telegram может повторить доставку. Ведётся учёт завершённых этапов, но абсолютное exactly-once невозможно: если Telegram принял отправку, а подтверждение потерялось до записи отметки, возможен повтор ответа. Отчёты не теряются намеренным ранним 200.

На 20.10.2026 официальная документация недоступна из рабочей среды (CONNECT 403). Перед созданием проверьте в панели актуальные бесплатные квоты, ограничения времени и условия некоммерческого использования Hobby. Не выбирайте платный план или автоматическое платное расширение. Ссылки для проверки: https://vercel.com/docs/functions/limitations , https://vercel.com/docs/plans/hobby , https://upstash.com/pricing/redis . Бесплатность и доступность Redis не подтверждены для вашего аккаунта.

Render Free Web Service — резервная альтернатива, но холодный старт, остановки и возможная повторная доставка требуют такой же проверки и внешних блокировок. Он не устраняет необходимость контроля повторов, поэтому перенос пока не выбран. Платный worker не создаётся.

## 1. Импорт сайта

1. Откройте https://vercel.com/new , войдите через GitHub и выберите личный Hobby-аккаунт.
2. Import Git Repository → `yurdamandurdyev/Test`, ветка `main`. При отсутствии репозитория предоставьте Vercel GitHub App доступ только к нему.
3. Root Directory: корень (`./`). Framework: Vite. Install: `npm ci`. Build: `npm run build`. Output: `dist`. Node.js: 24.x. Python определяется проектом (3.12+).
4. Для первого публичного запуска секреты не обязательны: сайт показывает данные задания, загрузка своей CRM закрыта. Deploy.
5. Откройте адрес Production deployment. Убедитесь, что посетителю не требуется Vercel-login. Если защита deployment включена, выключите её только для публичного Production; preview можно оставить закрытым. Не используйте защитный bypass-токен в webhook URL.
6. Пришлите публичный адрес для браузерной приёмки. Если сборка не прошла, передайте текст ошибки без секретов; локальная сборка не доказывает совместимость hosted runtime.

## 2. Серверные секреты

Project → Settings → Environment Variables → Production. Все значения только в защищённых полях, без `VITE_`:

| Имя | Значение |
|---|---|
| TELEGRAM_BOT_TOKEN | Токен BotFather |
| TELEGRAM_ALLOWED_USER_IDS | Ваш числовой User ID; несколько через запятую |
| TELEGRAM_WEBHOOK_SECRET | Случайный секрет минимум 32 символа; латиница, цифры, `_` или `-` |
| UPSTASH_REDIS_REST_URL | HTTPS REST URL созданного Redis |
| UPSTASH_REDIS_REST_TOKEN | Секретный REST token Redis |
| APP_PASSWORD | Случайный пароль команды ≥16 символов, если нужна загрузка CSV на сайте |
| SESSION_SECRET | Независимый случайный секрет ≥32 символов для веб-сессий |
| COOKIE_SECURE | `true` |

Storage / Marketplace → Upstash Redis → проверьте Free, создайте базу, подключите Production. Если интеграция выдала другие имена переменных, добавьте приведённые выше имена с соответствующими значениями. Не публикуйте REST token в браузере. Redeploy после изменения переменных. Для приватной веб-загрузки включите доступные средства ограничения `/api/login` в Firewall; локальный memory rate limiter не является глобальным serverless-лимитером.

## 3. Безопасное определение Telegram ID

До установки webhook остановите polling. Отправьте `/start` своему боту из личного чата. В рабочей среде установите токен через секреты и выполните:

```bash
.venv/bin/python scripts/telegram_setup.py identity
```

Скрипт читает `getUpdates`, выводит только числовые ID отправителей `/start` и имя бота; имена/сообщения/токен не печатает. Подтвердите, какой ID ваш, не разрешайте все найденные. Если webhook уже установлен, скрипт его не удаляет: используйте экспорт своих данных Telegram Desktop → Settings → Advanced → Export Telegram data, где указан собственный ID. Не отправляйте токен сторонним ботам «для определения ID».

## 4. Регистрация webhook

В защищённом окружении запуска скрипта должны быть те же `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` и `PUBLIC_BASE_URL=https://ваш-проект.vercel.app` (без завершающего пути). Не вводите секреты аргументами команд или в истории shell.

```bash
.venv/bin/python scripts/telegram_setup.py register
.venv/bin/python scripts/telegram_setup.py status
```

`register` проверяет Bot API, устанавливает секретный заголовок, `max_connections=1`, message и callback_query updates, не удаляет ожидающие обновления. Скрипт не меняет Vercel env. Проверка статуса не выводит потенциально чувствительные ошибки Telegram. Токен Vercel не нужен. Telegram должен обращаться к Production URL без редиректа на login.

## 5. Реальная приёмка

1. В браузере без входа: 8 записей CRM за неделю, 3 за день, средние 6 916 666,67 и 8 000 000; пять звонков, 57,95% по четырём разговорам, 46,36% по пяти попыткам. Телефоны — метки контактов.
2. CRM: фильтр «Сайт» даёт одну запись; поиск, JSON и маскированный CSV. Звонок 4 — 55/110, сброс — N/A. Открыть расшифровку. Скачать PDF, одна A4. Повторить на телефоне.
3. Разрешённый Telegram ID: `/start`, исходный CSV → та же сводка и `leads-normalized.csv`. Сравнить экспорт с результатом автономного Python-скрипта. Нельзя сымитировать входящий пользовательский документ только токеном Bot API; этот шаг выполняет человек.
4. Повторный файл в течение 10 минут → сообщение о повторе. Некорректные заголовки → понятная ошибка. >2 МБ → отказ до скачивания. Файл другого формата → отказ.
5. Другой ID и групповой чат → аналитика недоступна. Без секретного заголовка POST `/api/telegram/webhook` → 403. Никогда не публикуйте секретный заголовок в скриншоте.
6. `status` → webhook настроен, pending updates после обработки 0, delivery error отсутствует. После перезапуска функции повтор одного update_id не должен запускать расчёт снова (автотест покрывает ветку; реальную повторную доставку проверять только в закрытом окружении).
7. Веб-загрузка после входа: другой CSV пересчитывает показатели, экспорт совпадает с Python; после logout загруженные строки исчезают. Без пароля загрузка закрыта.

Без URL, серверных секретов, ID и пользовательской отправки CSV реальные пункты 1–7 не считаются выполненными. Mock-тесты транспорта явно отделены от живой проверки.
